# SPEC：5v5 四分钟巨兽 / 结算面板重排 / 首页布局优化 / 版本号 X.Y.Z

> 日期：2026-11-17　目标版本：4.12.0（versionCode 51）
> 关联：`SPEC-5v5-facing-minimap-levels-timing.md`（4.11 节奏与等级基线）、`AGENTS.md`
> 范围：仅 Godot 主线；3v3 玩法、节奏、数值、外观保持冻结；Web 存档不动。

## 0. 背景与目标

用户四项反馈：

1. **5v5 峡谷巨兽改为 4:00 出现**（当前与 5:00 终极对决同帧）。
2. **5v5 结算表最下面两行没有信息**，结算面板 UI 需要优化。
3. **首页 UI 排布需要优化**。
4. **版本号必须是 X.Y.Z 格式**（当前 `4.11.0-dev.2` 不符合）。

目标：巨兽出场与终极对决解耦、结算表结构上保证每人一行完整信息、首页整理为「品牌头 → 英雄网格 → 底部操作栏」、版本号改为纯 `4.12.0` 并把规则写入 AGENTS.md。

## 1. 5v5 巨兽 4:00（与终极对决解耦）

### 1.1 现状
- `battle_sim.step()` 在 `clock >= sudden_death_time` 同时置 `sudden_death=true` 与 `spawn_boss()`，播报合并为一条（`spawn_boss` 内「终极对决！…巨兽加入战场」）。
- 5v5：`sudden_death_time=300`；3v3：`180`（冻结）。

### 1.2 设计
- 新增独立 `boss_time` 字段：
  - 默认值 = `sudden_death_time`（3v3 行为逐位不变）。
  - `mode_5v5.boss_time = 240`（4:00）。
- `step()`：`clock >= boss_time` 只出巨兽；`clock >= sudden_death_time` 只进入终极对决。
- 播报：
  - 3v3（`boss_time == sudden_death_time`）保持原文案「终极对决！蓝/红方峡谷巨兽加入战场」。
  - 5v5 巨兽单独出场文案：「峡谷巨兽出现！蓝/红方巨兽加入战场」；5:00 终极对决播报不新增（`lbl_sudden` 面板已常驻提示），避免两条横幅叠字。
- 调试参数 `--boss` / `--boss-fly` 改用 `sim.boss_time`。
- 数值只进 `data/rules.json`，代码只读不写死。

### 1.3 验收
- 5v5：239s 无巨兽且未终极对决；240s 有巨兽、未终极对决；299s 同上；300s 终极对决（巨兽已在场，不重复生成）。
- 3v3：179s 无；180s 同时出巨兽 + 终极对决（文案与旧版一致）。
- 无头 10 局 5v5 仍全绿，时长不因 4:00 巨兽出现而异常（报告平均时长/超时数/早结束数）。

## 2. 结算面板重排（5v5 十人完整信息）

### 2.1 现状与问题
- 单张表 10 行 × 3 列数字（击杀/死亡/输出），每行 41px@1080p，行内只有像素数字与头像；实机反馈最下面两行没有信息，且信息密度、分区、可读性都差。
- 底部仅有「再来一局 / 回首页」两枚按钮，标题、比分、用时散落。

### 2.2 新布局（比例相对 Safe Rect）
面板：`x=0.125w, y=0.055h, w=0.75w, h=0.89h`，深色底 + 顶部 6px 金色条。

从上到下：
| 区块 | 位置（面板内） | 内容 |
|---|---|---|
| 标题 | y 0.012–0.085 | 「胜利！」/「差一点点！」，字号 0.050h |
| 结束原因 | y 0.088–0.132 | 如「水晶被摧毁」，字号 0.024h |
| 比分条 | y 0.150–0.200 | 「蓝队 2 : 1 红队」+ 右侧「用时 6:12」，深色凹槽 |
| 双方战绩卡 | y 0.218–0.862 | 左右两卡，间距 0.02w；每卡宽 (0.96w−gap)/2 |
| 底部提示 | y 0.872–0.905 | 「金色边框 = 你 · ★ = 输出最高」，字号 0.017h |
| 按钮 | y 0.915–0.995 | 「再来一局」（金）/「回首页」（深绿），各 0.30w，居中并排 |

双方战绩卡（左蓝右红，卡头用队伍色条）：
- 卡头 0.085×卡高：队伍名「蓝队 / 红队」+ 该队总击杀。
- 列头 0.055×卡高：英雄 / 等级 / 击杀·死亡 / 输出（字号 0.016h）。
- 行区剩余高度按 `team_size` 均分（5v5 五行 / 3v3 三行），行间距 3px。
- 每行固定内容：
  - 头像：`min(row_h*0.68, 卡宽*0.12)`，带 1px 描边；
  - 姓名：「（你）」金色，其余蓝/红浅色；占位 `?` 兜底；
  - 等级：「Lv4」；
  - 击杀·死亡：「2 / 3」；
  - 输出：像素数字右对齐（金色仅玩家）。
- 玩家行：金色 2px 外框 + 左侧 5px 金条。
- MVP：全场输出最高者头像右上角金色 ★（`ui_star`），输出为 0 不评。

### 2.3 实现要点
- 删除「10 行全宽表」实现，新增 `_result_team_rect(team)` / `_result_row_rect(team, i)` / `_result_team_header_rect` / `_result_col_header_rect`。
- 新增 Label：队伍名 ×2、比分、用时、列头 ×8、等级 ×10、击杀死亡 ×10；姓名沿用 `lbl_res_names`（10 个）。
- `_update_panel_labels()` 统一隐藏/摆放所有结算 Label；`_draw_result_bg()` 画面板/卡/行底/按钮，`_draw_result_icons()` 画头像/MVP/玩家描边。
- 结构性兜底：即使某队人数不足 `team_size`，缺位行显示「—」，不出现只有底色的空行。
- 保留输入矩形函数名 `result_restart_rect()` / `result_home_rect()`，`input_hub.gd` 不改。

### 2.4 验收
- 5v5 结算：10 行（每队 5 行）每行都有头像、姓名、等级、击杀/死亡、输出；最下面两行必须有内容（像素级检查）。
- 3v3 结算：每队 3 行，同样字段完整。
- 底部两枚按钮文字可见；标题、比分、用时、提示互不重叠。
- 桌面 1280×720 与 1920×1080 两种分辨率渲染检查。

## 3. 首页布局优化

### 3.1 现状
- 标题居中、副标题在下方；英雄网格 0.245–0.735h（5v5 三行被压到 163px/卡）。
- 模式按钮（0.095w×0.06h）与难度按钮（0.13w×0.082h）分散在左下两行，开始按钮孤立在右下，版本号贴在右下角；控件大小/间距不统一。

### 3.2 新布局（相对 Safe Rect）
| 区块 | 位置 | 内容 |
|---|---|---|
| 品牌头 | x 0.045–0.505w，y 0.022–0.147h | 金色描边面板；「萌兽峡谷」左对齐 0.072h；副标题 0.026h |
| 版本徽章 | x 0.78–0.955w，y 0.045–0.085h | 「v4.12.0 · Godot 4.7.2」右对齐 0.020h |
| 英雄网格 | x 0.045–0.955w，y 0.185–0.730h | 5 列；3v3 两行、5v5 三行；卡间距 1%w |
| 操作栏 | x 0.045–0.955w，y 0.752–0.940h | 深色面板，内含模式/难度分段 + 开始按钮 |
| 提示行 | 操作栏内左侧标签行右侧 | 「10/15 位英雄 · 点卡片看技能」0.019h |

操作栏内部（栏内坐标，栏高 0.188h）：
- 标签行 y 0.018–0.046：左侧「模式」、x 0.30w 处「难度」。
- 控件行 y 0.055–0.163：
  - 模式：3v3 / 5v5 各 0.075w×0.108h，x 0.02w 起，间距 0.008w；
  - 难度：轻松 / 挑战 各 0.095w×0.108h，x 0.30w 起，间距 0.008w；
  - 开始：0.22w×0.108h，右对齐距栏右 0.02w，金色 + ▶ + 「开始冒险」0.036h；
  - 提示文字置于难度组与开始按钮之间，居中。
- 触控热区：所有按钮高度 ≥0.10h（1080p 下 ≥108px），远大于 44vp。
- 删除右下角旧 `lbl_foot` 底部署名，改为右上版本徽章；引擎版本显示 4.7.2。

英雄卡片保持原有交互（点击弹详情、金框选中、职业色条）；5v5 三行卡高从 ~163px 提升到 ~184px@1080p。

### 3.3 验收
- 3v3（10 卡）与 5v5（15 卡）网格不压操作栏、不超出安全区；任意两控件矩形不相交。
- 模式切换后网格重排、选中英雄仍高亮；难度/开始点击行为不变（`flow_headless` 全绿）。
- 版本徽章显示 `v4.12.0 · Godot 4.7.2`。
- 1920×1080 渲染逐项量矩形与文字存在像素。
